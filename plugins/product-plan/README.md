# product-plan

产品规划技能插件：覆盖**需求建档 → PRD 体系维护**的产品规划工作，产出 Git 友好、AI 可检索的产品需求文档。

## 技能

### requirement-prd（自研）

需求期 PRD 撰写技能：为单个未上线需求撰写结构化需求文档，完全独立使用。从对话上下文综合成文（系统化澄清可配合 thinking 插件的 interview-me / grilling），按需求形态套用规范化骨架——单功能需求按功能类型裁剪、跨模块流程需求用流程骨架、全局定义增量按全局规范表结构起草拟新增条目、横切通用能力与新模块各有对应骨架。行为级章节（流程 / 字段 / 规则 / 状态 / 权限 / 异常 / 验收）一律写目标行为，验收场景可衡量可推演，拿不准的规则以待确认标记求证。文档存 `docs/requirements/`（进行中直接放根目录、文件名带 `MM-DD-` 日期前缀，已合并归档至 `archive/<年-月>/`；或贴入任务系统工作项），未上线前不进主 PRD；章节与表头固定规范，与主流主 PRD 体系天然对齐，上线确认后可零转换融入。

### project-prd（自研）

PRD 体系管理技能：在软件项目中建立并持续维护一套 Git 友好、AI 可检索的产品需求文档体系——四层 `prd/` 目录（产品总览 / 全局规范 / 业务模块 / 跨模块流程）。核心纪律：主 PRD 只描述当前生产环境，增量需求在外部任务系统管理、上线后才融入；持续更新不做版本副本，历史交给 Git Commit 与 Tag。覆盖三类工作流：初始化 prd/ 体系、融合已上线需求（含跨模块影响检查）、PRD 质量检查。内置完整管理规范（`references/prd-spec.md`）、12 类标准文档模板库（`references/templates/`，每类模板独立成文件，按文档类型分轻量化 / 规则化 / 精细化三档严格程度）与交付前机械检查脚本（`scripts/prd-check.py`，ERROR/WARN 分级：悬空链接、索引登记、占位符与指引残留、结构体量嫌疑）。

装好即用，在目标项目里对 Claude 直接说：

- **"初始化 PRD 目录"** → 新建 docs/prd/ 体系并套用模板
- **"给 XX 需求写个 PRD"** → 撰写需求期 PRD（规范化结构，上线后可顺畅融入主 PRD）
- **"XX 功能已上线，把它合并进 PRD"** → 融合增量需求（含跨模块影响检查与提交前门禁）
- **"检查一下 PRD"** → 质量审查，输出问题清单

## 关联插件

- 需求澄清与方案打磨（访谈 / 发散 / 拷问 / 领域建模）在 **thinking** 插件，两插件配合覆盖"想清楚 → 写下来"全链。
- 拆解建票在 **issue-tracker** 插件的 `to-issues`，流转追踪在 `issue-tracker` 技能。
- 原型相关技能见 **prototype-design** 插件（`prototype-app` 可执行镜像原型 / `prototype` 即抛式发散对比）。
