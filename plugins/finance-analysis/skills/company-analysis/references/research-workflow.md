# 研究与交付流程

公司级 `sources/` 保存原件，`sources.json` 登记来源和哈希；每个 run 的 `analysis/research.md` 合并蓝图、六项基础预检、研究交接、证据覆盖、数值勾稽和逐项缺口。评分与估值各用自己的工件目录，不另建任务状态文件或发布数据库。

## 创建与资料

使用 `company_run.py start --company-dir <绝对路径> --company <名称>` 创建 run，调用路径按 [SKILL.md 的入口约定](../SKILL.md#脚本入口与调用)。`start` 自动生成 `runs/<run-id>/analysis/research.md`，包含 15 行报告蓝图、六项基础预检及指标覆盖、勾稽、交接和缺口等表格；按生成骨架填写，无需另建模板。取数前完成公司专项蓝图、基础口径，并确定[估值单位](valuation/valuation-contract.md#估值单位)。正式章节在输入冻结后写。

原件登记使用 `company_run.py add-source --company-dir DIR --file FILE --url URL --publisher 发布方 --period 报告期 --locator 定位`。已核验网页可仅提供 URL；本地原件保存哈希。公司目录内文件直接登记相对路径，外部文件才复制；重复登记会核验原件，外部复制件遗失但原文件可读时自动恢复。引用旧 `materials/` 或历史 run 原件同样登记，不迁移旧资料；原件变动须重新登记。

把返回的来源编号写入事实 `source_material_id`、正文引用及来源清单，保留文件、机构、期间、链接、页码/章节。来源细节和失败处理统一见[取数路线](research/source-access.md)。

## 子智能体名额安排

优先级：五个方向研究员 → 三位专职评审（评分一位、估值提议与批判两位）→ 冻结前反方 → 临时专项。研究是产出主体，名额紧张时优先保障研究方向并行；评审在事实冻结后启动，不与研究争名额。

按环境提供的并发槽位和累计限制安排：已确认只有并发限制，第一层两个方向并行启动，交付后依次启动第二、三层，评审在研究完成后分批创建；明确存在累计上限或不能确认完成任务是否释放创建名额时，按依赖层次逐层创建研究员（第一层行业与同业、财务与现金流并行，底稿交回后启动第二层，再第三层），评审名额视剩余情况创建，不足则排队等待已完成的子代理释放名额。创建研究、反方或专项失败时，协调者用相同方法完成并记录执行者及原因，不遗漏分析。

三位评审（评分者、估值者、估值批判者）是不同的专职子代理，研究员、反方和协调者不转任。并发不足排队，草稿修正交回原槽位。确实无法取得足额评审名额时保留可恢复 run 和冻结输入，说明环境限制并取得可用名额；不能把协调者卡片当作独立评审。

## 研究交接

五个方向按[行业与同业](../../../agents/researcher-industry.md)、[财务与现金流](../../../agents/researcher-financial.md)、[业务与护城河](../../../agents/researcher-business.md)、[资本配置与股东](../../../agents/researcher-capital.md)、[风险与反证](../../../agents/researcher-risk.md)研究员 agent 执行（类型 `finance-analysis:researcher-*`），收到同一蓝图和已登记共用资料，交付按各自 agent 文件引用的交付模板写入 run。行序即依赖顺序：行业与同业、财务与现金流并行启动；业务与护城河接收同业池与盈利核对，资本配置与股东接收现金流事实；风险与反证最后汇集四份报告。可并行时创建子代理，否则协调者按同一顺序逐方向完成，保留 02–11 章全部研究责任。

执行者按[取数路线](research/source-access.md)自主取数和补证。每份底稿交付：

| 内容 | 要求 |
|---|---|
| 候选事实 | 数值、单位、期间、范围、审计状态、原件及定位；定性主张也有定位 |
| 分析 | 必要计算、同口径历史/同业比较、初步判断与最强反例 |
| 缺口 | 逐项字段、已查来源与结果或未查理由、替代证据、对评分/估值的影响 |

子代理不并发修改共用 `sources.json`、`analysis/research.md` 或冻结输入。协调者核验冲突、去重并统一登记最终采用的来源；搜索片段和二手观点仅作线索。汇齐后补查可能改变判断的缺口，形成底稿和公司专项估值候选。

## 按需专项任务

仅当问题、原件和交付范围可独立界定，且影响关键比较、评分或估值时拆专项，如复杂同业、特殊行业口径或重大事件。先由所属方向处理，确需拆出且评审名额已保障才建子代理；无名额则顺序执行。

研究交接表记录所属方向、执行者、问题、原件范围和影响章节。专项按相同交付要求产出候选底稿；所属方向核对口径、冲突并合并，协调者最终登记。冻结前完成合并，未解决差异作为缺口或反例保留。

## 反方审视与输入预检

底稿汇齐后按[反方审视 agent](../../../agents/challenger.md)审视；有名额可独立分派，否则记录“协调者自审”。检查表保存挑战、支持/反对证据定位、裁决与理由、修正动作及对输入或置信度的影响。补证和实质修正在冻结前处理，未解决挑战写成假设或缺口。

完成资料、单位和口径预检后，按[评分输入准备](scoring/scoring-contract.md#协调者输入准备)逐维匹配证据，按[估值输入准备](valuation/valuation-contract.md#协调者输入准备)准备方法与计算输入。两边 `preflight-input` 就绪、事实 ID 与内容一致才冻结、分派。新 run 检查已核验披露事实的登记来源及本地原件哈希，旧 run 不追溯新契约。

## 研究检查表

- **核心指标覆盖：** 逐项标明已展示、缺口或不适用；一个独立缺口一行，`Gxx-xx` 连接研究记录和受影响章节，不把无关字段合并。
- **关键数值勾稽：** 对影响结论的派生数保留代入数、公式、期间和单位，尤其收入拆分、CFO/净利润、现金覆盖债务和每股估值；正文新增数字回填复核。
- **缺口记录：** 写字段、期间、章节、实际已查来源与结果或未查理由、替代依据和置信度影响。技术故障、未披露、未到披露期、口径不符分别记录。

缺口不能取消评分、估值或发布。无法恢复原件时，把对应事实改为未核验线索或有依据的假设，保留旧来源编号和定位并说明影响；仍标已核验会报错。补查记录不全或覆盖/勾稽空项只给警示，如实写入报告；逐项经济正确性由协调者复核。

## 报告交付

评分和估值完成后，按[报告规范](report-format.md)写完 15 章，在检查表记录最终结论审视：支持/反对证据、分歧裁决、数值勾稽、机器结果与措辞一致性、置信度和推翻条件。措辞或引用错误在本 run 修正；冻结事实数值、尺度、币种、份额或经济含义改变则新建 run，保留原运行。

最终使用 `company_run.py publish --run-dir RUN --report FILE`。它内部执行完整 `check`；需要提前排错时才单独运行 `check`，内容变化后仍由发布入口重验。机器检查覆盖章节顺序/状态、覆盖项、引用及评分估值终态，不替代实质复核。

报告 `[S1]`、`[S1、S2]` 引用及冻结事实的本地原件核验哈希，范围引用逐项展开；仅 URL 来源核对登记而不重下载，未使用的归档资料不扫描。已核验事实原件缺失/变化须修正；未核验线索旧来源、缺口记录不全和冻结来源未列入报告只给警示并说明限制。

`publish` 固定本 run 的 `reports/analysis.md`、更新公司级 `reports/latest.md` 并锁定完成状态；预览可用 `--no-latest`。同内容重复发布返回原文件，完成后修改须新 run；历史资料与报告保留。
