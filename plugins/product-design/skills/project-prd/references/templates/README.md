# PRD 标准文档模板库

12 类标准文档模板，每类一个文件。配套管理规范见 [../prd-spec.md](../prd-spec.md)。

## 使用方式（先读）

**模板是结构参考，不是必须填写的表格**，不强制把 12 份模板复制到每个项目。所有 `【填写内容】` 都是占位符；标注「按需」的章节，没有对应内容时直接删除；以"写…"“仅当…时填写”“与第 X 章…”等开头的说明性段落是给撰写者的指引，套用时一并删除，不带入项目文档。模板内的相对链接（如 `../00-overview/roles.md`）按最终 `prd/` 目录中的目标位置书写，复制到项目后即生效。

按文档类型分三个严格程度：

| 严格程度 | 文档 | 第一目标 |
|---|---|---|
| 轻量化 | 产品总览（00-overview）、模块 overview | 准确、清晰、容易导航 |
| 规则化 | 全局规范（01-foundation）、跨模块流程（03-workflows） | 统一定义、清晰引用、业务逻辑一致 |
| 精细化 | 功能级 PRD | 明确字段、状态、操作、约束、异常与预期业务结果 |

功能级 PRD 的第 3～9 章（功能详细说明 / 业务规则 / 状态管理 / 权限控制 / 异常与边界 / 关联业务行为 / 业务验收场景）直接决定 AI Agent 能否准确理解系统如何运行，作为填写与审查的重点。

## 按功能类型裁剪功能 PRD

模板 11 是通用基础，不同类型的功能按需裁剪章节，不为凑模板强行编写无关章节。

| 功能类型 | 重点描述 | 可弱化或省略 |
|---|---|---|
| 业务单据型（采购单、运输单） | 字段、操作、状态流转、业务规则、关联对象 | 无关的界面细节 |
| 流程审批型 | 审批角色、流转条件、驳回、撤回、历史记录 | 大量普通字段描述 |
| 数据查询型（报表、统计） | 指标口径、筛选条件、统计维度、权限、导出 | 状态管理 |
| 配置管理型（规则配置、参数配置） | 配置项、默认值、生效范围、优先级、约束 | 复杂业务流程 |
| 自动处理型（定时任务、自动对账） | 触发条件、执行规则、幂等、失败重试、业务结果 | 页面交互 |
| 外部集成型 | 业务触发、数据映射、同步规则、异常与一致性 | 与产品无关的技术实现 |

例如库存统计报表的 PRD，最重要的是库存数量如何计算、统计时间点、哪些数据纳入统计、不同角色能看到什么——没有必要强行编写状态流转章节。

各功能类型的**必答项**（写作时逐一回答，不要求套满全部章节）：

- 查询类：数据范围、空结果表现、重复请求行为
- 配置类：默认值、配置来源、生效条件
- 自动任务类：漏跑补偿、幂等性
- 指标类：计算公式、去重口径、零分母处理
- 业务单据 / 审批 / 外部集成类：按上表「重点描述」列执行

## 统一编写规则

1. **规则必须明确、可验证。** 避免"支持灵活审批""自动处理异常"这类模糊表述；明确触发条件、判断规则、处理动作和最终结果。
2. **引用代替复制。** 共享定义只在权威文档维护，其他文档通过相对路径引用，必要时链接到具体章节。
3. **文件路径保持稳定。** 以业务能力命名文件，不用版本号和开发任务编号命名主 PRD；历史由 Git 管理。
4. **简单功能不强制拆分。** 复杂度较高时再拆分文件，避免产生几百个只有几行内容的 PRD；一份文档最好能独立描述完整的业务能力。
5. **所有描述以生产现状为准。** 主 PRD 中不出现"下一期支持""未来考虑""计划增加"等内容；已发布但仅对部分用户开放的功能，明确适用范围。
6. **待确认内容统一标注。** 没有把握的内容用 `<!-- 待确认：原因 -->` 行内注释标记，便于检索清点；产品确认后移除标记，不留 TODO 类杂散标记。
7. **引用共享规则注明具体位置。** 引用 01-foundation 或其他文档的规则时，注明具体规则编号或章节（如 `business-rules.md` 的 BR-001），不只链整个文件——避免"链接目标存在但缺少被引用内容"的语义死链。
