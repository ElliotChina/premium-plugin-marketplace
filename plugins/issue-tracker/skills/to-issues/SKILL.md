# To Tickets

把一份 PRD、方案或计划拆成一组**工单**发布到项目的跟踪器。工单怎么建、关联怎么挂，全部按 issue-tracker 技能执行，本技能只负责拆解与确认。

## 流程

### 1. 收集输入

- 参数给了路径（需求 PRD、方案文档）→ 读全文
- 参数给了工作项编号 → 按 issue-tracker 的 view 读取（含评论）
- 无参数 → 用当前对话里已形成的方案
- 未探索过代码库则先探索现状：既有模式、约定、可预重构点（先让改变容易，再做容易的改变）。工单措辞用项目的领域词汇

### 2. 拆垂直切片

- 每片**窄而完整**地贯穿所有层（数据、接口、界面、测试），完成后独立可演示或可验证；不做「先全部数据层、再全部接口层」的水平切分
- 大小以一个新上下文窗口能装下为准。再拆的信号：标题里出现「和」、验收标准写不满 3 条、横跨两个独立子系统
- 每片声明**阻塞边**：哪些片完成之前它不能开始
- **宽重构例外**：单一机械变更波及全库（改共享类型、挪字段），垂直切无法保持每片可用——按 expand-contract 排序：先加新形态与新形态共存（expand），分批迁移调用方、每批一票（每片保持可用），最后删旧形态（contract）
- 高风险的片尽量排前，尽早暴露问题

### 3. 与用户确认

把拆解结果编号列出，每片展示：**标题**、**阻塞于**哪些片、**交付**什么端到端行为。问三件事：

- 粒度对吗（太粗 / 太细）？
- 阻塞边对吗（是否真被它列出的片卡住）？
- 有要合并或再拆的吗？

迭代到用户认可为止。**未经确认不发布。**

### 4. 发布

按 issue-tracker 技能执行（读 `.claude/issue-tracker.md` 确定跟踪器）：

- 发布前先检索目标跟踪器：同一需求已有工单（未关闭）则停下询问，不重复建
- 按依赖顺序逐票 **create**（阻塞别人的先建），类型用 `task`；拆的是需求本身（大需求分子需求）用 `requirement`
- 阻塞关系逐票 **link blocks**；来源是某个父需求 / 父工单时 **link parent**
- 票正文按 issue-tracker 的工作项模板组织，「背景」一节写本票交付的端到端行为（用户视角），验收标准写成可勾选清单
- 票正文不写具体文件路径和代码片段（很快过期）；确有决策性代码（schema、类型定义）可内联并注明来源
- 来源是已有工作项时，只新增子票，**不关闭、不修改**来源

全部建完后向用户汇报工单编号清单与依赖顺序；首个无阻塞的票可以顺势问一句是否现在开始做。
